# 需求说明

## 用户与业务目标

目标用户是内容团队的审核人员和排期负责人。系统需要找出待处理素材，结合元数据、审核规则、硬性发布时间和已有排期，形成无冲突、可确认的发布排期草稿。

系统辅助决策，不替代最终人工确认，也不执行真实发布。

## 输入

- 请求标识 `request_id`；
- 一个或多个素材 ID；
- 每项素材的硬性要求发布时间；
- 可选的用户确认信息；
- 仅用于合成验收的工具失败注入。

本地材料包含素材元数据、审核规则和已有排期。所有内容均为合成数据。

## 输出

每项素材必须返回：

- 审核状态；
- 风险原因或缺失字段；
- 用户要求时间和建议时间；
- 待确认事项；
- 草稿保存状态及草稿 ID；
- `published=false` 安全标识。

## 动态决策要求

Planner 每轮根据现有观察选择下一动作：读取素材、规则检查、时段查询、登记确认、保存草稿或结束。它必须根据工具返回的缺失信息、规则风险、时段冲突和保存错误调整后续动作。

未经用户确认，不得把替代时段写成已接受的硬性要求。原 `requested_time` 始终保留；替代时间仅写入 `suggested_time` 和待确认草稿。

## 范围

范围内：CLI、模型接入、离线 Mock、本地业务工具、Trace、幂等草稿保存、步数上限、自动化测试和文档。

范围外：真实发布、生产数据库、账号权限、消息通知、界面、线上部署、多 Agent 和生产级 Runtime。

## 成功标准

1. 正常排期能够保存草稿，但不声称已发布。
2. 信息缺失时登记补充项，不检查或保存不可靠排期。
3. 阻断级规则风险停止排期并返回原因。
4. 时段冲突时建议可用替代时间并等待确认。
5. 同一请求重复保存只产生一条草稿。
6. 保存失败明确返回失败，不伪装成功。
7. 达到步数上限时明确返回未完成状态。
8. 至少两条路径体现根据不同工具结果选择不同后续动作。
