# 需求说明

## 用户与目标

用户是内容审核和排期团队。目标是根据素材元数据、审核规则、发布时间要求和已有排期，形成无冲突、可确认的发布草稿。

## 输入与输出

输入包含请求 ID、素材 ID 和版本、硬性时间或时间窗口，以及可选的用户确认。业务材料位于 `data/`。

每项结果必须返回审核状态、风险原因、原要求时间、建议时间、待确认项、草稿保存状态和 `published=false`。

## 成功标准

1. 正常素材能够保存草稿。
2. 信息不足时请求补充，不进入排期。
3. 阻断风险停止排期并返回原因。
4. M01 的 18:00 冲突后建议 19:00，未经确认不保存。
5. 用户接受 19:00 后重新查询，仍可用才保存。
6. 相同请求重复执行只产生一份草稿。
7. 保存失败不得虚报成功。
8. 达到执行上限返回明确未完成状态。
9. 至少两条真实模型 Trace 显示模型根据工具结果调整动作；目标是全部八条在线 Trace。

## 范围

范围内包括 CLI、DeepSeek Planner、离线 Mock、本地工具、JSON 草稿存储、测试和 Trace。界面、部署、多 Agent、生产数据库、鉴权和真实发布不在范围内。
