# 项目复盘

## 实际投入

累计主动实现与验证约 75 分钟，包含数据精简、预期合同、uv 环境、代码、测试和文档；不包含等待用户确认和工具网络等待。建议剩余时间用于轮换密钥、生成在线 Trace、人工审查和最终提交。

## 最难问题

最难的是区分三个独立状态：用户原始硬性时间、Agent 建议时间、草稿持久化结果。早期设计把“等待确认”和“保存成功”混在同一个状态中；最终拆成 `save_status` 与 `workflow_status`，并根据用户决定改为确认前不保存。

重复提交也需要同时处理排期查询和幂等保存：查询时必须忽略同一请求自己的草稿，否则第二次执行会把自己视为冲突；保存时仍要比较负载指纹，防止相同请求 ID 静默覆盖不同内容。

## 学习收获

- 动态决策不能只靠提示词，关键边界必须由 Runtime 校验。
- Trace 应记录简短业务依据，而不是模型隐藏思维过程。
- 离线 Mock 对可复现测试有价值，但不能冒充真实模型证据。
- “没有发布工具”是比“提示模型不要发布”更可靠的权限边界。
